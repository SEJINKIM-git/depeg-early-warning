# 스테이블코인 배경지식 온보딩 문서

> **대상**: 핀테크·블록체인 배경지식이 전혀 없는 신규 랩 멤버
> **목적**: 디페그 조기경보 + 대응 자동화 시스템 프로젝트 착수 전 필수 개념 이해
> **작성**: 랩장

---

## 1. 스테이블코인이란 무엇인가

### 1-1. 한 줄 정의

- 스테이블코인 = **가치가 특정 자산(주로 달러)에 1:1로 고정되도록 설계된 디지털 화폐**임
- "1코인 = 1달러"라는 약속을 지키는 것이 존재 이유의 전부인 코인임

### 1-2. 비유: 카지노 칩

- 카지노에 입장하면 현금을 칩으로 바꾸는 것과 동일한 구조임
  - 현금 10만 원 → 칩 10만 원어치 교환
  - 카지노 안에서는 칩으로 게임 참여
  - 나갈 때 칩을 다시 현금으로 환전
- 스테이블코인도 마찬가지임
  - 달러를 코인으로 바꿔서 블록체인이라는 "카지노 안"에서 사용
  - 언제든 다시 달러로 바꿀 수 있다는 **믿음**이 핵심
- 중요한 포인트: 칩 자체는 플라스틱 조각일 뿐이며, 가치의 원천은 **"카지노 금고에 내 현금이 보관되어 있다"는 신뢰**임

### 1-3. 왜 필요한가: 비트코인의 문제

- 비트코인·이더리움 같은 일반 암호화폐는 하루에 10~20%씩 가격이 출렁이는 자산임
- 비유: **가격표가 매시간 바뀌는 편의점**
  - 아침에 1,500원이던 삼각김밥이 저녁에 3,000원이 된다면 화폐로 사용 불가능함
  - 월급을 비트코인으로 받으면 다음 날 월급이 반토막 날 수도 있는 것
- 결제·송금·정산 같은 실용적 기능에는 **가치가 흔들리지 않는 디지털 화폐**가 필요했고, 그 답이 스테이블코인임
- 현재 대표 주자: USDT(테더), USDC(서클) — 두 코인의 시가총액 합계가 스테이블코인 시장 대부분을 차지함

## 2. 페그(Peg): 1코인 = 1달러라는 약속

### 2-1. 페그의 의미

- 페그(peg) = 못, 말뚝이라는 뜻의 영어 단어임
- 코인 가치를 달러라는 말뚝에 **묶어 놓는 것**을 의미함
- "페그가 유지된다" = 시장에서 1코인이 실제로 1달러 근처(예: $0.999 ~ $1.001)에 거래되고 있다는 뜻임

### 2-2. 페그는 어떻게 유지되는가: 두 가지 방식

**방식 A. 준비금 담보형 (USDT, USDC 등 주류 방식)**

- 비유: **문화상품권 발행사**
  - 상품권 1만 원권을 발행하려면 발행사가 1만 원의 실제 자산을 금고에 보관해야 함
  - 사용자가 상품권을 들고 오면 언제든 현금 1만 원으로 교환해줘야 함
- 발행사는 코인 발행량만큼의 달러·미국 단기국채(T-bill)를 **준비금(reserve)**으로 보유함
- 페그 유지 원리 = **차익거래(arbitrage)**
  - 시장에서 코인이 $0.98로 떨어지면 → 누군가 싸게 사서 발행사에 $1.00로 환매 → 매수세 유입 → 가격 회복
  - 시장에서 코인이 $1.02로 오르면 → 누군가 발행사에서 $1.00에 새로 발행받아 시장에 매도 → 가격 하락
  - 즉 "언제든 1달러에 교환 가능"하다는 사실 자체가 가격을 1달러로 되돌리는 자동 복원 장치임

**방식 B. 알고리즘형 (실패한 방식)**

- 실제 달러 준비금 없이, 다른 코인과의 교환 알고리즘만으로 1달러를 유지하려던 방식임
- 비유: **담보 없이 "내 회사 주식으로 갚겠다"는 차용증**
  - 회사가 잘나갈 때는 문제없지만, 회사 신뢰가 무너지는 순간 차용증과 주식이 동시에 휴지조각이 되는 구조임
- 2022년 한국 개발자가 만든 테라(UST)가 이 방식이었고, 약 60조 원 규모가 일주일 만에 증발하며 붕괴함
- 이 사건 이후 글로벌 규제 흐름은 "준비금 담보형만 인정"하는 방향으로 정리됨

## 3. 디페그(Depeg): 약속이 깨지는 순간

### 3-1. 디페그의 정의

- 디페그 = 코인 가격이 1달러에서 **이탈**하는 현상임
- 소폭 이탈(±0.5% 이내)은 일상적으로 발생하며 곧 회복됨
- 문제는 이탈 폭이 커지고 회복되지 않는 경우이며, 이것이 본 프로젝트가 탐지하려는 대상임

### 3-2. 비유: 뱅크런(은행 대량 인출 사태)

- 디페그의 본질은 **디지털 뱅크런**임
- 은행 뱅크런의 전개 과정과 완전히 동일한 구조임
  1. "저 은행 금고에 돈이 없다더라"는 소문 발생
  2. 불안해진 예금자들이 앞다투어 인출 시도
  3. 은행은 모든 예금을 현금으로 들고 있지 않으므로(일부는 대출·채권에 묶여 있음) 인출 요청을 즉시 다 못 받아줌
  4. "역시 돈이 없구나" → 공포 확산 → 인출 폭주 → 실제 파산
- 핵심 통찰: **처음 소문이 사실이 아니어도, 모두가 믿고 행동하면 현실이 되는 자기실현적 붕괴**임
- 스테이블코인도 동일함
  - "발행사 준비금이 부실하다"는 의심 → 대량 환매 + 시장 투매 → 가격 하락 → 공포 가속 → 디페그 심화

### 3-3. 실제 사례 두 가지 (프로젝트 백테스트 시나리오)

**사례 1. 테라 UST 붕괴 (2022년 5월)**

- 알고리즘형의 구조적 결함이 터진 사례임
- $1.00 → $0.98 → $0.60 → $0.10 이하로 일주일 만에 추락, 사실상 0으로 수렴함
- 교훈: 준비금 없는 페그는 신뢰가 흔들리는 순간 복원 장치가 작동하지 않음

**사례 2. USDC 디페그 (2023년 3월)**

- 준비금 담보형도 안전하지 않음을 보여준 사례임
- USDC 발행사(서클)가 준비금 일부를 실리콘밸리은행(SVB)에 예치했는데, 그 **은행이** 파산함
- 비유: 문화상품권 발행사는 멀쩡한데, **발행사가 돈을 맡긴 은행이 무너진 것**
- USDC는 $0.87까지 하락했으나, 미국 정부가 SVB 예금 전액 보호를 발표하자 이틀 만에 $1.00 회복함
- 교훈 1: 디페그 리스크는 코인 자체가 아니라 **준비금이 어디에 어떻게 보관되어 있는가**에서 발생함
- 교훈 2: 조기 경보가 있었다면 하락 초기에 대응(노출 축소, 헤지)이 가능했던 사건임 — 본 프로젝트의 존재 이유

## 4. 준비금과 공시: 신뢰를 검증하는 방법

### 4-1. 준비금 구성이 중요한 이유

- "준비금 100% 보유"라는 말만으로는 부족하며, **무엇으로** 보유하는지가 핵심임
- 비유: **전당포의 담보물 품질**
  - 현금 담보 = 즉시 돌려줄 수 있음 (최고 품질)
  - 미국 단기국채 = 며칠 내 현금화 가능 (양호)
  - 회사채·기업어음 = 시장 상황에 따라 제값에 못 팔 수 있음 (위험)
- 준비금의 **유동성 구성**이 부실할수록, 대량 환매 요청 시 버티지 못하고 디페그로 이어질 확률이 높음

### 4-2. Attestation(검증 보고서)

- 발행사들은 회계법인을 통해 "발행량 대비 준비금이 충분한지" 검증 보고서를 정기 공시함
- 비유: **음식점 위생등급 인증서**
  - 인증서가 있으면 일단 신뢰 가능하지만, 검사 빈도·검사 범위·검사 기관의 수준이 제각각임
  - 월 1회 간이 점검(attestation)과 연 1회 전면 감사(audit)는 신뢰도가 다름
- 본 프로젝트에서 이 공시 PDF들을 자동 수집·구조화하는 파이프라인이 오프체인 시그널의 핵심 입력이 됨

## 5. 온체인 vs 오프체인: 우리가 다룰 두 종류의 데이터

- **온체인(on-chain) 데이터** = 블록체인 위에 기록되어 누구나 실시간 열람 가능한 데이터임
  - 비유: **모두에게 공개된 유리 금고** — 입출금 내역이 전부 투명하게 보이는 것
  - 예시: 코인 발행량·소각량, 거래소 가격, 유동성 풀 잔고, 대형 지갑의 이동
- **오프체인(off-chain) 데이터** = 블록체인 바깥의 현실 세계 정보임
  - 비유: 유리 금고 **바깥의 뉴스와 서류** — 금고는 투명해도, 금고 주인 회사의 재무 상태는 서류를 봐야 아는 것
  - 예시: 준비금 공시 보고서, 발행사 관련 뉴스, 규제 발표, 예치 은행의 건전성
- USDC 사태의 교훈: 온체인만 보면 멀쩡했으나 오프체인(SVB 파산)에서 위기가 시작됨 → **두 데이터를 결합해야 진짜 조기경보가 가능함**

## 6. 규제 환경: 지금이 왜 골든타임인가

- 2025년 7월, 미국이 GENIUS Act라는 연방 스테이블코인 법을 제정함 — 준비금 요건, 환매 절차, 감사 의무를 법으로 강제하는 체계임
- 유럽(MiCA), 홍콩(2026년 첫 라이선스 발급) 등도 각자의 인가 체계를 가동 중임
- 한국은 **원화 스테이블코인** 발행을 허용하는 디지털자산기본법 입법을 추진 중이며, 은행권·빅테크가 발행 주도권을 놓고 경쟁하는 국면임
- 비유: **자동차는 이미 도로를 달리는데 도로교통법이 이제 만들어지는 상황**
  - 법이 확정되면 준비금 모니터링·리스크 감시 시스템은 선택이 아닌 **의무**가 됨
  - 규제 확정 직전에 감시 시스템을 먼저 설계해보는 것이 본 랩의 전략적 포지션임

## 7. 산업 맥락: 빅테크가 금융이 되는 시대

### 7-1. 사례: "뱅크 오브 엔비디아"

- 2026년 8월, 엔비디아가 골드만삭스·블랙록·블랙스톤·아폴로·브룩필드·KKR 등 월가 6대 금융사와 5,000억 달러(약 700조 원) 규모의 AI 인프라 자금조달 플랫폼 구축 MOU를 체결함
- 구조: GPU와 데이터센터를 **담보**로 대출을 일으키는 것 — 시장에서 "뱅크 오브 엔비디아"라는 별칭이 붙을 정도로, 반도체 기업이 사실상 금융 플랫폼으로 변신 중임
- 비유: **건물주가 건물을 담보로 대출받는 것과 동일한 구조** — 다만 담보가 부동산이 아니라 반도체 칩이라는 점이 새로운 것
- 주의 깊게 볼 리스크: 엔비디아가 GPU 가치 하락 위험의 일부(최소 25%)를 스스로 떠안는 구조라 "순환금융" 우려가 제기됨
  - 순환금융 비유: **내가 내 가게 손님에게 돈을 빌려주고, 그 돈으로 손님이 내 가게 물건을 사는 구조** — 매출은 늘어 보이지만 리스크가 시스템 안에서 돌고 있는 것

### 7-2. 스테이블코인과의 연결고리

- 엔비디아 플랫폼 자체는 스테이블코인 사업이 아님 — 그러나 본 프로젝트와 두 가지 지점에서 연결됨
- **연결 1: 정산 레이어의 온체인 전환**
  - 기관 금융이 온체인으로 이동하는 흐름 속에서, 대규모 자금의 결제·정산 수단으로 스테이블코인이 유력한 후보임
  - 실제로 비자(Visa)는 금융기관용 스테이블코인 발행·정산·관리 통합 플랫폼(VSP)을 출시함 — 기관용 스테이블코인 인프라 경쟁이 이미 시작된 것
- **연결 2: 구조적 동형성 (본 프로젝트 관점에서 가장 중요)**
  - GPU 담보 대출의 핵심 리스크 = "담보(GPU)의 가치가 유지되는가"를 감시하는 문제
  - 스테이블코인의 핵심 리스크 = "준비금의 가치가 유지되는가"를 감시하는 문제
  - 즉 둘 다 **담보 가치 감시 → 리스크 스코어링 → 이해관계자별 대응**이라는 동일한 시스템 문제임
  - 전당포 비유의 확장: 전당포가 맡은 물건이 국채든 GPU든, **"맡긴 물건의 값어치를 실시간으로 감시하는 시스템"이 필요하다는 본질은 같은 것**

### 7-3. 우리 랩 관점에서의 의미

- 반도체(YieldWatch)와 핀테크(본 프로젝트)라는 랩의 두 도메인이 별개가 아니라, 실제 산업에서 **"반도체가 금융 담보가 되는" 형태로 융합되고 있다는 증거**임
- 본 랩의 "탐지 → 영향평가 → 역할별 대응" 아키텍처가 특정 도메인에 종속되지 않는 이유를 보여주는 사례임 — 감시 대상이 수율이든, 준비금이든, GPU 담보 가치든 시스템 설계의 본질은 동일함
- 디페그 조기경보 시스템에서 검증한 아키텍처는 향후 실물·기술 자산 담보 금융(RWA)의 리스크 감시로 확장 가능한 것

---

## 8. 본 프로젝트와의 연결: 왜 "디페그 조기경보 + 대응 자동화"인가

### 8-1. 탐지만으로는 부족함

- 가격 이탈 알림은 거래소 앱도 제공하는 기능이며, 그것만으로는 차별화가 안 됨
- 화재 비유로 정리하면:
  - **화재 감지기** = 이상 탐지 (누구나 만듦)
  - **스프링클러 + 대피 방송 + 소방서 자동 신고** = 대응 자동화 (본 랩이 만들 것)
- 우리 시스템의 3단계 구조
  1. **탐지**: 온체인 + 오프체인 시그널 결합으로 디페그 리스크 스코어 산출
  2. **영향 평가**: 리스크가 현실화될 경우 누구에게 얼마나 큰 손실인지 정량화
  3. **역할별 대응**: 같은 경보라도 받는 사람에 따라 다른 정보를 전달함

### 8-2. 역할별 대응의 예시 (Role-based Alert Design)

- 동일한 "리스크 스코어 급등" 상황에서:
  - **트레저리 담당자** → 보유 노출 규모와 축소 시나리오(어떤 순서로 얼마나 팔지) 제시
  - **컴플라이언스 담당자** → 공시 의무·보고 체크리스트 자동 생성
  - **일반 사용자** → "지금 환매 시 예상 손실 vs 대기 시 리스크"를 쉬운 언어로 안내
- 화재 비유의 연장: 같은 화재 경보라도 **소방관, 건물주, 입주민이 받아야 할 안내가 전혀 다른 것**과 같음

### 8-3. 기존 랩 프로젝트와의 관계

- YieldWatch AI(반도체 수율)의 "탐지 → 영향 스코어링 → 역할별 알림" 아키텍처 패턴을 도메인만 바꿔 재사용하는 것임
- 즉, 스테이블코인이 생소하더라도 **시스템 설계 관점에서는 이미 우리가 해본 문제**임

## 9. 핵심 용어 정리 (치트시트)

| 용어 | 한 줄 설명 | 비유 |
|---|---|---|
| 스테이블코인 | 1달러에 가치가 고정된 디지털 화폐 | 카지노 칩 |
| 페그 | 1코인 = 1달러라는 고정 관계 | 말뚝에 묶인 밧줄 |
| 디페그 | 페그가 깨져 가격이 이탈하는 현상 | 뱅크런 |
| 준비금 | 발행량만큼 보유하는 실물 자산 | 상품권 발행사의 금고 |
| 환매(redemption) | 코인을 발행사에 반납하고 달러를 돌려받는 것 | 칩을 현금으로 교환 |
| 차익거래 | 가격 괴리를 이용한 매매로 페그를 복원시키는 힘 | 자동 복원 스프링 |
| Attestation | 준비금 보유를 검증하는 정기 보고서 | 위생등급 인증서 |
| 온체인 데이터 | 블록체인에 공개 기록된 데이터 | 유리 금고 내부 |
| 오프체인 데이터 | 블록체인 바깥의 현실 정보 | 금고 밖 뉴스와 서류 |
| 유동성 풀 | 코인을 즉시 교환할 수 있는 거래 자금 창고 | 환전소의 현금 보유고 |
| 순환금융 | 판매자가 구매자에게 자금을 대주는 자기참조적 구조 | 내 가게 손님에게 빌려준 돈으로 내 물건을 사게 하는 것 |
| RWA(실물자산 토큰화) | 부동산·GPU 등 실물 자산을 온체인 금융에 연결하는 것 | 건물 등기부를 디지털 증서로 만드는 것 |
