# 데이터 출처와 수집 경로

이 문서는 현재 저장소의 실행 코드와 저장된 데이터에 근거한다. `source: "onchain"`은
Signal 계약의 분류값이며, 현재 가격 관측은 블록체인 노드가 아니라 **Bitstamp 거래소의
USDC/USD 시장**에서 온다.

## 실제 외부 데이터: Bitstamp USDC/USD

| 항목 | 확인된 내용 |
| --- | --- |
| 출처/API | Bitstamp Public API, `https://www.bitstamp.net/api/v2/ohlc/usdcusd/` |
| 수집 경로 | `python -m scripts.collect_bitstamp_usdc --start ... --end ...` → `fetch_signals_range` → `fetch_signals` → HTTP GET → `rows_to_signals` → Signal v1 JSON 표준 출력 |
| 요청 | `step=3600`(1시간), Unix epoch 초 단위의 `start`·`end`, 요청별 `limit`(최대 1,000행). 긴 구간은 최대 999시간씩 나눈다. 완료된 캔들만 요청하며 `end`는 현재 UTC 정각보다 늦을 수 없다. |
| 응답과 사용 필드 | JSON `data.ohlc` 배열의 `timestamp`와 `close`만 Signal 계산에 사용한다. 다른 OHLC 필드와 거래량은 현재 Signal에 사용하지 않는다. |
| 출력 필드·단위 | `price_usd`: USDC 1개당 USD, 1시간 캔들 종가. `peg_deviation_bps`: `(price_usd - 1.0) × 10,000`을 소수 둘째 자리로 반올림한 부호 있는 bps. `source`는 `onchain`, `coin`은 `USDC`, `schema_version`은 1이다. |
| 접근 조건 | 기존 수집 기록에는 회원가입·API 키 없이 무료로 접근했다고 명시돼 있다. 정확한 호출 한도 및 현재의 접근·요금 조건은 **확인 필요**. 수집기는 정상 요청 사이 기본 1초 대기와 오류 재시도를 둔다. |

Bitstamp의 `timestamp`는 **UTC 1시간 캔들의 시작 시각**이다. 수집기의 `--start`는
포함, `--end`는 제외하므로 원시 캔들 범위는 `[start, end)`다. 코드의
`_bitstamp_candle_start_to_observed_at`이 이 값에 `BITSTAMP_STEP_SECONDS`(3,600초)를
더한다. 따라서 Signal의 `observed_at`은 **캔들 종료 후 종가 확정 시각**이며 범위는
`(start, end]`다. 예를 들어 `2023-03-09T00:00:00Z` 시작 캔들의 Signal 시각은
`2023-03-09T01:00:00Z`다. `signal_id`에도 이 종료 시각이 들어간다. ISO 8601 입력
시각은 시간대가 있어야 하며 Unix epoch 초도 입력할 수 있다. 내부와 출력은 UTC
`YYYY-MM-DDTHH:MM:SSZ`로 정규화한다.

`rows_to_signals`는 요청 범위 밖 응답 행을 제외하고 시작 시각으로 정렬한다. 범위 안의
시간별 캔들이 빠졌거나 시각이 중복·정시 간격에서 벗어나면 오류를 낸다. `close`가 없거나
유한하지 않거나 음수이면 오류를 낸다. 긴 구간을 합친 뒤에도 Signal 시각의 연속성·중복을
검사한다. 결측 가격을 보간하거나 중복 행을 임의로 선택하지 않는다.

성공한 HTTP 응답 body는 기본적으로 `data/raw/bitstamp/usdcusd/`에 요청 구간별 원본
bytes로 저장한다. 검증에 실패한 body는 `failed/` 아래에 격리한다. 동일한 파일명의
기존 body가 다르면 덮어쓰지 않고 오류를 낸다. 변환된 과거 Signal 파일은
`data/historical/`에 보관한다. 이 저장소에서 확인되는 두 구간은 다음과 같다.

| 파일 | 원시 캔들 시작 범위 `[start, end)` | Signal 시각 범위 `(start, end]` | 시간별 캔들 / Signal |
| --- | --- | --- | ---: |
| `signals_usdc_2023_calm_hourly.json` | `2023-01-15T00:00:00Z`–`2023-02-12T00:00:00Z` | `2023-01-15T01:00:00Z`–`2023-02-12T00:00:00Z` | 672 / 1,344 |
| `signals_usdc_2023_depeg_hourly.json` | `2023-03-09T00:00:00Z`–`2023-03-14T00:00:00Z` | `2023-03-09T01:00:00Z`–`2023-03-14T00:00:00Z` | 120 / 240 |

이 파일들의 이전 수집 기록과 재수집 raw 해시, 재생성 절차는
[historical README](../data/historical/README.md)에 있다. 이 작업 트리에는
`data/raw/bitstamp/usdcusd/`의 두 구간별 JSON 파일이 있다. 최초 수집 raw body와
현재 파일의 동일성은 **확인 필요**다.

## 로컬 예시와 미구현 경로

`main.py`는 `data/mock/signals_usdc_sample.json`과
`data/mock/signals_usdc_crisis.json`을 읽는 로컬 데모다. 이 파일은 mock 시나리오이며
Bitstamp API에서 수집한 원시 데이터로 취급하지 않는다. mock 파일 각 값의 개별 원천과
생성 절차는 **확인 필요**다.

`src/intelligence/attestation_parser.py`는 이미 파싱된 현금·단기국채 비중을 Signal로
바꾸는 함수만 제공한다. PDF 읽기 및 실제 attestation 수집은 TODO 상태다. 특정 발행사
문서나 외부 API를 현재 수집 출처로 기재할 근거는 없다. 스키마에 정의된 다른 지표도
실제 수집 파이프라인이 있다는 뜻은 아니다.
